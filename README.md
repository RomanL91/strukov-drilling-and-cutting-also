# Струков — сверление и резка

Десктопное приложение (Flet): берёт производственные задания из МойСклад,
раскладывает номенклатуру по профилям и отправляет задание на линию сверления
и резки.

## Что делает

1. **Задания** — список производственных заданий из МойСклад с поиском,
   постраничной навигацией, датой, статусом и числом позиций.
2. **Разбор** — по каждой позиции читает атрибуты номенклатуры и собирает
   комплект профилей, размножая его по плановому количеству:

   | Тип | Атрибуты МойСклад |
   |---|---|
   | `Osnov` (Основной) | `Длина профиля "Основной"`, `Кол-во "Основного"`, `Сверление` |
   | `Per` (Перемычка) | `Длина профиля "Перемычка"`, `Кол-во "Перемычек"` |
   | `Otrag` (Отражатель) | `Длина профиля "Отрожатель"` |

3. **Сводка** — таблица того, что уйдёт на станок (число отрезков, суммарная
   длина), плюс список замечаний по позициям с незаполненными или
   нераспознанными атрибутами.
4. **Отправка** — задание уходит на станок GET-запросом по адресу вида
   `http://<хост>:<порт>/?{tasks:[{s:854,n:2,d:[250,354],oc:"Osnov",cli:"3-0326-207-1"}]}`.
   Есть подтверждение перед отправкой, а также «Копировать URL» и
   «Открыть в браузере».

## Протокол станка (iPAP2)

Реализовано по документу «Описание протокола передачи данных линии сверления
и отреза ALSO» от 12.11.2025.

- **Перед отправкой запрашивается состояние** `{status_request:1}`. Пока
  оборудование занято (`state=2`), оно молча игнорирует команды, поэтому
  отправка блокируется с понятным сообщением.
- **Ответ разбирается**, а не только код HTTP: станок отвечает `200 OK` даже
  на отклонённый пакет, реальный итог лежит в поле `tasks` (`1` — принят,
  `2` — отклонён, код ошибки бежит строкой на панели станка).
- **Одинаковые блоки сливаются** — количество задаётся полем `n`, поэтому
  вместо 30 повторов уходит 3 блока (пакет L001: 1216 → 157 байт).
- **Проверяются лимиты**, отправка блокируется при нарушении:

  | Ограничение | Значение |
  |---|---|
  | `s` — размер | до 4 цифр (≤ 9999 мм) |
  | `n` — количество | до 3 цифр (≤ 999 шт) |
  | `d` — сверловки | до 2 отступов |
  | `oc` — код заказа | ≤ 8 символов |
  | `cli` — имя клиента | ≤ 12 символов |
  | заданий в пакете | ≤ 100 |
  | TCP-пакет | ≤ 2953 байт |

- **Кириллица и спецсимволы** (`#`, `%`, `'`, `*`, `^`, пробел) кодируются в
  URL по приложению А документа. Символы вне поддерживаемого набора
  отбрасываются с предупреждением — иначе панель выдаёт ошибку 67/77.

Сетевые требования из документа: оборудование `192.168.0.100`, маска
`255.255.0.0`, порт `8080`; управляющий компьютер должен иметь адрес
`192.168.0.108`.

## Запуск

```bash
poetry install
poetry run python main.py     # или: make run
make dev                      # с горячей перезагрузкой
```

Требуется Python ≥ 3.11.

## Настройки

Задаются в приложении на вкладке «Настройки»: логин и пароль МойСклад, адрес
API, IP и порт станка, таймаут запросов, размер страницы списка.

Хранятся в JSON:

- Windows: `%APPDATA%\StrukovDrilling\config.json`
- macOS: `~/Library/Application Support/StrukovDrilling/config.json`

При первом запуске значения подхватываются из `.env` (`MS_LOGIN`,
`MS_PASSWORD`), если он лежит рядом с проектом. **Пароль хранится в конфиге в
открытом виде.**

Логи с суточной ротацией:

- Windows: `%LOCALAPPDATA%\StrukovDrilling\logs\`
- macOS: `~/Library/Logs/StrukovDrilling/`

## Сборка

```bash
make build-windows    # .exe, запускать на Windows
make build-macos      # .app, запускать только на macOS
```

Метаданные сборки (имя, идентификатор бандла, права доступа) заданы в
`pyproject.toml`, секция `[tool.flet]` — локальная сборка и сборка в CI дают
одинаковый результат.

### Про macOS

`flet build macos` работает **только на macOS**: бандл собирает Flutter, а ему
нужен Xcode. С Windows и из Linux-контейнеров это невозможно — контейнеров с
macOS не существует.

Есть два рабочих пути.

**1. Запуск из исходников** — проще всего для внутреннего инструмента, не нужны
ни Xcode, ни подпись, ни обход Gatekeeper:

```bash
brew install python@3.11 poetry
poetry install
poetry run python main.py
```

**2. Сборка `.app` через GitHub Actions** — `.github/workflows/build-macos.yml`.
Запускается вручную (`workflow_dispatch`), при пуше в `main` и по тегу `v*`;
для тега дополнительно создаётся релиз с приложенным архивом.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Флет сам ставит нужный Flutter (сейчас 3.44.8) в `~/flutter/<версия>` —
в workflow этот каталог кешируется, иначе каждая сборка тратит минуты на
скачивание гигабайта. Минуты macOS на GitHub тарифицируются с множителем 10×,
поэтому включена отмена незавершённых сборок той же ветки.

Собранное приложение **не подписано**, и macOS заблокирует первый запуск.
Снять карантин:

```bash
xattr -dr com.apple.quarantine /путь/к/StrukovDrilling.app
```

Либо правый клик по приложению → «Открыть» → «Открыть». Чтобы приложение
открывалось обычным двойным щелчком, нужен Apple Developer Program
(99 $ в год) и нотаризация.

## Архитектура

Слои и направление зависимостей — каждый следующий знает о предыдущих,
обратное запрещено:

```
domain          модели, справочники, интерфейсы; без ввода-вывода
application     сценарии использования поверх интерфейсов домена
infrastructure  реализации интерфейсов: HTTP, МойСклад, протокол станка
ui              экраны Flet поверх фасада приложения
core            пути, настройки и журнал
```

```
main.py                                 точка входа, ft.run()

app/domain/models.py                    ProductionTask, CutRow, Job, MachinePacket…
app/domain/profiles.py                  справочник типов профилей
app/domain/interfaces.py                TaskRepository, MachineGateway, PacketBuilder…
app/domain/errors.py                    иерархия ошибок

app/application/job_assembler.py        загрузка → разбор → сведение → пакет
app/application/production_service.py   фасад для интерфейса
app/application/container.py            композиционный корень

app/infrastructure/http/                транспорт и политика повторов
app/infrastructure/moysklad/            клиент, преобразователь, репозиторий, разбор атрибутов
app/infrastructure/machine/             ограничения iPAP2, кодировщик, сборщик, шлюз

app/ui/base_view.py                     общая схема выполнения операций
app/ui/                                 экраны: список, задание, настройки
```

### Как это соответствует SOLID

- **Единственная ответственность.** Кодирование значений, проверка ограничений,
  сборка адреса, транспорт и разбор ответа — пять отдельных классов вместо
  одного модуля. Загрузка данных (`MoySkladTaskRepository`) отделена от их
  осмысления (`AttributeProfileExtractor`).
- **Открытость/закрытость.** Типы профилей вынесены в `ProfileCatalog`:
  новый профиль — это новая запись справочника, а не правка разбора.
  Ограничения протокола вынесены в `ProtocolLimits`.
- **Подстановка.** Наследование используется только там, где оно уместно
  (`BaseView`); связи между слоями построены на `typing.Protocol`.
- **Разделение интерфейсов.** Интерфейсы узкие: у `MachineGateway` две
  операции, у `PacketBuilder` — одна.
- **Инверсия зависимостей.** `ProductionService` и `JobAssembler` зависят
  только от интерфейсов домена; конкретные классы подставляет
  `ServiceContainer`. Благодаря этому сценарии проверяются без сети —
  подменными репозиторием и шлюзом.

### Применённые паттерны

| Паттерн | Где | Зачем |
|---|---|---|
| Репозиторий | `MoySkladTaskRepository` | Скрывает пути API и пагинацию |
| Преобразователь данных | `ProductionTaskMapper` | Знание о формате JSON в одном месте |
| Шлюз | `AlsoMachineGateway` | Сценарии не знают про HTTP и формат ответа |
| Строитель | `AlsoPacketBuilder` | Пошаговая сборка адреса пакета |
| Фасад | `ProductionService` | Четыре операции для интерфейса |
| Фабрика | `ServiceContainer` | Единственное место связывания зависимостей |
| Шаблонный метод | `BaseView.run_action` | Общая схема «занят → выполнить → ошибка» |
| Объект-значение | модели `domain/models.py` | Неизменяемые данные между слоями |
